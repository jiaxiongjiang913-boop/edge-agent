# 参考文献核验与来源追溯

这是辅助当前 Agent 核对书目信息的工作流，不是自动判断“假论文”的分类器。

## 输入
参考文献列表或本机文件、输出目录；保留用户的原始序号和原始文本，原文件默认只读。

## 逐条核对
1. 解析题名、作者、年份、刊物、卷期页码或文章号、DOI；缺失项留空。规范化 DOI 时移除 `https://doi.org/` 前缀和外围标点，不更改原始输入。
2. 有 DOI：在真实网页打开 DOI 链接和最终出版方页面，对照条目信息。注意 DOI 能打开不代表其对应用户引用的那篇论文。
3. 无 DOI 或 DOI 不匹配：在真实学术站点的搜索框输入题名，必要时组合作者、年份；打开匹配候选的出版方页面读书目信息。预印本、会议版和期刊版分别记录，不擅自合并。
4. 出版方为主要核对来源；索引平台、Crossref、机构库可作交叉来源。每条保留实际打开的链接、访问日期、字段差异与证据说明。单一站点未检索到不是不存在的证据。
5. 只有查到出版方正式撤稿/更正公告时记录相应状态并给公告链接；不要把书目信息匹配等同于研究质量可靠。
6. 遇验证码、权限不足或页面故障时保留待核查状态，不伪造结果。按已完成数/总数报告进度，下载和输出遵守当前数据盘规则。

## 结果状态
- **信息一致**：可追溯来源与该条的核心书目信息一致。
- **信息不匹配**：找到明确来源，但 DOI、题名、作者、年份等存在差异；逐项列出。
- **待核查**：证据不足、无法访问、候选歧义或尚未找到。不得改写为“虚假”。

## 输出字段
`original_id,original_reference,status,matched_title,matched_authors,matched_year,matched_journal,matched_doi,differences,publisher_url,crosscheck_url,accessed_at,notes`

输出 CSV/JSON 核验表，并附信息一致、不匹配、待核查三类数量。建议修正另列，未经用户要求不覆盖原参考文献文件。

## 示例给 Agent 的指令
请按本模板逐条核对【参考文献文件/列表】，重点检查 DOI 是否对应题名、作者和年份；附出版方来源，把不匹配和证据不足项列出来，结果写入【数据盘输出目录】，保留原始参考文献。
